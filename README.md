# Pac-Man — Ghosts! More ghosts!

## Description

A complete, playable remake of the classic arcade game **Pac-Man**, written in
Python with `pygame` and an object-oriented, modular architecture.

The player navigates a maze, eats every pacgum to clear the level, avoids the
ghosts, and uses super-pacgums to turn the tables and eat the ghosts for a short
time. The game features multiple procedurally generated levels, a persistent
highscore board, a configurable ruleset loaded from a JSON file, and a cheat
mode to make peer review easy.

Mazes are generated by an **external** `A-Maze-ing` package (used as-is, never
modified). The game is designed to be packaged and deployed to a public gaming
platform.

## Instructions

Requirements: **Python 3.10+** and [`uv`](https://docs.astral.sh/uv/).

```bash
# Install dependencies (into a local virtual environment)
make install            # runs: uv sync

# Run the game (defaults to ./src/config/config.json)
make run                # runs: uv run python -m src ./src/config/config.json

# Run with a custom config
uv run python -m src path/to/config.json

# Run under the Python debugger (pdb)
make debug

# Lint (flake8 + mypy)
make lint
make lint-strict        # stricter mypy pass

# Remove caches / temporary files
make clean
```

The program takes **exactly one argument**: a `.json` configuration file. Any
error (missing file, wrong extension, invalid content) is reported with a clear
message — never a Python traceback.

### Controls

| Action                | Keys                          |
| --------------------- | ----------------------------- |
| Move                  | Arrow keys **or** `W A S D`   |
| Pause / resume        | `Esc`                         |
| Toggle invincibility  | `I` (cheat)                   |
| Skip current level    | `P` (cheat)                   |

Gameplay: eat all pacgums to win a level; eat a super-pacgum (corner) to make
ghosts edible; eat an edible ghost for bonus points; avoid ghosts otherwise or
lose a life. You start with 3 lives and each level has a time limit.

## Configuration

The configuration is a JSON file. In addition to standard JSON, the loader also
accepts **comments**:

- `#` line comments (custom pre-processing),
- `//` and `/* ... */` comments (via `json5`).

The top level is a list containing a single configuration object. Supported keys
(all optional — robust defaults are applied):

| Key                        | Default        | Notes                                              |
| -------------------------- | -------------- | -------------------------------------------------- |
| `highscore_filename`       | `score.json`   | Must end with `.json`; stored under `src/score/`.  |
| `levels`                   | 10 default lvl | List of `{ "name", "width" (≥10), "height" (≥10) }`. At least 10 levels. |
| `lives`                    | `3`            | Starting lives (≥3).                               |
| `points_per_pacgum`        | `10`           | Score for eating a pacgum (≥1).                    |
| `points_per_super_pacgum`  | `50`           | Score for eating a super-pacgum (≥1).              |
| `points_per_ghost`         | `200`          | Score for eating an edible ghost (≥1).             |
| `seed`                     | `42`           | Fixed seed used for the first level.               |
| `level_max_time`           | `90`           | Per-level time limit in seconds (≥60).             |

### Faulty configuration handling

Configuration parsing never crashes the game. On a missing key or an invalid
value, the parser **clamps the offending field to its safe default, logs a clear
message, and continues**. Unknown keys are ignored. If the whole file is missing
or is not valid JSON, a clear error message is printed and the program exits with
a non-zero status (no traceback). See `src/parsing/parser.py` (`Parser._sanitize`
/ `Parser._repair`).

## Highscore

Highscores are **persisted to disk** as a JSON file (default `src/score/score.json`).

- Only the **top 10** scores are kept (sorted descending) — both on save and on
  display.
- Player names are limited to **10 characters, alphanumeric and spaces only**
  (invalid characters are filtered as they are typed).
- Scores are non-negative integers; malformed or negative entries in the file
  are ignored on load.
- Loading is **robust to file errors**: a missing file, corrupt JSON, a
  non-list root, or malformed entries all yield an empty/clean list instead of a
  crash.

Persistence is centralized in `src/entity/score.py` (`load_highscores`,
`save_highscore`, `sanitize_name_char`). This keeps the file format in one place,
makes the top-10 / validation rules easy to reason about, and lets both the
highscore screen and the end-of-game screen share the exact same behavior.

## Maze Generation

Mazes are generated by the assigned **external `A-Maze-ing` package**
(`mazegenerator`, vendored as `mazegenerator-2.0.2-py3-none-any.whl` and declared
as a dependency in `pyproject.toml`). The package is used **as-is**; our loader
adapts to its interface, not the other way around.

- The `PERFECT` parameter defaults to `False`, producing Pac-Man-compatible
  corridors (loops, not a perfect tree).
- The **first level** uses the fixed `seed` from the config, so it is
  reproducible. **Subsequent levels** are generated without a fixed seed, i.e.
  randomly.
- If the generator fails, the error is handled cleanly.

Integration lives in `src/__main__.py` (first maze) and
`src/scenes/in_game.py` (`generate_maze`, subsequent levels).

## Implementation

- **Language / stack**: Python 3.10+, `pygame` for rendering and input,
  `pydantic` for typed/validated configuration, `json5` for comment-aware JSON.
- **Entry point**: `python -m src <config.json>` (`src/__main__.py`) — validates
  the CLI argument, loads the config, initializes pygame, and runs the main loop.
- **Scene state machine**: the main loop dispatches to the current scene
  (`GameState` enum) each frame; scenes return the next state.
- **Ghost AI**: each ghost is driven by a pluggable *strategy*
  (`src/strategies/`): aggressive (A\* chase), random roaming, zone roaming,
  retreat (flee when edible), and return-to-spawn (after being eaten). Pathing
  uses A\* over open cells.
- **Config robustness**: invalid values clamp to safe defaults and the game
  continues (see above).
- **Cheat mode**: invincibility toggle (`I`) and level skip (`P`) to help
  reviewers test features quickly.

## General Software Architecture

High-level module overview:

```
src/
├── __main__.py        # CLI parsing, pygame init, scene state machine / game loop
├── constant.py        # Screen size, colors, timings, paths, gameplay constants
├── parsing/           # parser.py — comment-aware JSON + pydantic Data/Level models
├── entity/            # Game objects
│   ├── entity.py      #   base Entity + Direction
│   ├── player.py      #   Pac-Man (movement, collisions, eating, lives)
│   ├── phantom.py     #   ghosts (delegate movement to a strategy)
│   ├── pacgum.py / superpacgum.py
│   ├── wall.py, sprite.py
│   └── score.py       #   Score counter + persistent highscore load/save/validation
├── strategies/        # Ghost behaviors (aggressive, random, zone, retreat, return_spawn) + A* (strategy.py)
├── scenes/            # UI + game screens
│   ├── scene.py       #   base Scene
│   ├── main_menu.py   #   Start / Highscores / Instructions / Exit
│   ├── in_game.py     #   maze build, HUD (score/lives/level/time), gameplay
│   ├── pause.py       #   resume / back to menu
│   ├── end_scene.py   #   shared win/lose base (final score + name entry)
│   ├── win.py, lose.py
│   ├── highscore.py, instruction.py
│   └── button/        #   reusable Button widget
├── config/            # Default config.json
├── score/             # Persistent highscore file
└── sprites/           # PNG assets
```

Relationships: `__main__` owns the scenes and the shared `Score`; scenes read
the parsed `Data` config and draw entities; `in_game` composes `Player`,
`Phantom`s, `Pacgum`s and `Wall`s from the generated maze; each `Phantom`
delegates its per-frame move to a `Strategy`; end/highscore scenes go through the
persistence helpers in `entity/score.py`.
